# Shannon 项目前端完整总结

## 📋 项目概览

Shannon 的前端是一个**多平台桌面应用**，基于 **Tauri 2** + **Next.js 16** + **React 19** 构建。代码位于 `desktop/` 目录，约 72 个核心源文件。它支持两种运行模式：

- **Web 模式**：`npm run dev` 启动 Next.js 开发服务器（快速测试）
- **原生桌面模式**：`npm run tauri:build` 打包为 macOS/Windows/Linux 安装包

技术栈：Next.js 16 (App Router) · shadcn/ui + Radix UI · Tailwind CSS 4 · Zustand + Redux Toolkit · Dexie.js · @xyflow/react · react-markdown · Tauri 2

## 🎯 核心功能模块

### 1. **路由结构**（`app/` 目录）

使用 Next.js 路由分组，**OSS 模式**默认跳过登录直接进入对话页：

| 路由                   | 文件                            | 功能                                          |
| ---------------------- | ------------------------------- | --------------------------------------------- |
| `/`                    | `app/page.tsx`                  | 根路由，自动跳转 `/run-detail?session_id=new` |
| `/run-detail`          | `app/(app)/run-detail/page.tsx` | **核心对话页**（最复杂，约 2365 行）          |
| `/runs`                | `app/(app)/runs/page.tsx`       | 历史会话列表（搜索、删除、重命名）            |
| `/agents`              | `app/(app)/agents/page.tsx`     | 选择 Everyday / Deep Research Agent           |
| `/skills`              | `app/(app)/skills/page.tsx`     | 浏览/调用可复用的 Agent 技能                  |
| `/schedules`           | `app/(app)/schedules/page.tsx`  | 定时任务管理（Cron 调度）                     |
| `/settings`            | `app/(app)/settings/page.tsx`   | 用户设置、API Key、Rate Limit                 |
| `/login` & `/register` | `app/(auth)/`                   | OSS 模式下直接重定向到对话页                  |

### 2. **对话管理（最核心模块）** ⭐

文件：`components/chat-input.tsx` + `app/(app)/run-detail/page.tsx` + `components/run-conversation.tsx`

**对话输入（ChatInput）**：

- **两种布局**：`default`（对话流底部紧凑）和 `centered`（ChatGPT 风格首屏居中）
- **Agent 类型选择器**：Everyday Agent（普通） / Deep Research（深研究） / Web Automation（浏览器自动化）
- **研究策略**：Quick / Standard / Deep / Academic（仅 Deep Research 显示）
- **HITL 自动审批开关**：On / Off（仅深研究显示）
- **Swarm Mode 切换**（仅 Everyday Agent）：启用多 Agent 持续循环
- **Skill 标签**：显示已选技能，可一键移除
- **运行时控制**：任务运行时输入框变成 **Pause（暂停）+ Stop（终止）** 两个按钮
- **IME 中文输入法支持**：`isComposing` ref 处理组合输入
- **快捷键**：Enter 发送、Shift+Enter 换行
- **预设建议**：centered 模式下显示 "Latest AI developments" / "Explain quantum computing" / "React vs Vue" 三个快捷 chip

**对话流（RunConversation）**：

- 消息角色：user / assistant / system / tool / status
- **流式输出**：实时累积 SSE `thread.message.delta` 事件，显示光标闪烁的流式渲染
- **Markdown 渲染**：`react-markdown` + `remark-gfm` + `rehype-highlight`（含代码高亮）
- **行内引用徽章**：自动识别 `[1][2]` 格式，鼠标悬停弹出 `CitationBadge` 显示来源
- **Sources 弹窗**：点击来源按钮显示 favicon 堆叠 + 引用列表（最多 5 个 favicon）
- **进度状态条（Pills）**：工具调用、思考、Agent 启动等以居中胶囊形式展示
- **截图消息**：浏览器自动化时显示 base64 截图，可点击放大
- **浏览器错误**：带倒计时的重试按钮（rate limit / timeout / not found）
- **复制按钮**：每条消息右下角一键复制
- **折叠中间消息**：通过 `isIntermediateMessage()` 过滤掉 `synthesis`、`reasoner-*` 等中间推理内容

### 3. **会话管理**

**侧边栏（AppSidebar）**：

- 5 个主导航：New Task / My Agents / Skills / Schedules / Settings
- **Recent Sessions 列表**：显示最近 10 个会话，自动按完成状态显示动画
- **状态指示器**：运行中（蓝色脉冲）、活跃（绿色）、非活跃（灰色）
- **行内重命名**：点击会话旁的「⋯」菜单 → Rename
- **AlertDialog 删除确认**：删除会话弹窗
- **Streaming Title 自动同步**：监听 Redux `sessionTitle`，流式生成会话标题时立即更新侧边栏
- **Theme Toggle**：日/月/暗模式切换

**历史页（/runs）**：

- 表格视图：Session / Agent / Tasks / Cost / Actions
- **搜索过滤**：按标题和 session_id
- **分页加载**：每次 50 条
- **Tooltip 详情**：任务数 Tooltip 显示成功/失败分布
- **Agent 类型图标**：Deep Research 紫色显微镜 / Everyday 黄色星

### 4. **HITL（人在环路）研究计划审核**

当 Deep Research 启用 Auto-Approve = Off 时：

- LLM 生成研究计划 → 通过 `RESEARCH_PLAN_READY` SSE 事件 → 进入 review 状态
- 顶部出现紫色 banner：「Research plan ready — approve to start execution」
- 计划作为带特殊样式（`isResearchPlan: true`）的 assistant 消息插入对话
- 用户可输入反馈（多轮对话）→ 提交 `submitReviewFeedback()` API（带 `If-Match` 乐观并发）
- LLM 检测 `intent`：feedback（继续讨论）/ ready（可批准）/ execute（直接执行）
- intent=ready 时显示 "Approve & Run" 按钮
- intent=execute 时自动调用 `approveReviewPlan()`

### 5. **任务控制**

- **暂停/恢复**：`POST /api/v1/tasks/:id/pause` / `resume`
- **取消**：`POST /api/v1/tasks/:id/cancel`，分两阶段：`workflow.cancelling` → `workflow.cancelled`
- **轮询兜底**：30 秒无新事件时主动 `getTask()` 检查状态
- **取消确认轮询**：每 2 秒检查一次直到任务真正停止

## 🔌 后端集成方式

### API 客户端：`lib/shannon/api.ts`

基础地址从环境变量 `NEXT_PUBLIC_API_URL` 读取（默认 `http://localhost:8080`），对应 Go 编排器的 HTTP Gateway。完整 API 端点：

| 类别          | 端点                                                           | 方法                     |
| ------------- | -------------------------------------------------------------- | ------------------------ |
| **认证**      | `/api/v1/auth/{register,login,refresh,me}`                     | POST/GET                 |
| **任务**      | `/api/v1/tasks`                                                | POST（创建）/GET（查询） |
| **任务控制**  | `/api/v1/tasks/:id/{pause,resume,cancel,control-state,review}` | POST/GET                 |
| **流（SSE）** | `/api/v1/stream/sse?workflow_id=xxx`                           | EventSource              |
| **会话**      | `/api/v1/sessions`                                             | GET/POST/PATCH/DELETE    |
| **会话事件**  | `/api/v1/sessions/:id/{events,history,files}`                  | GET                      |
| **工作区**    | `/api/v1/sessions/:id/files/:path`                             | GET                      |
| **Blob 引用** | `/api/v1/blobs/:blob_id`                                       | GET                      |
| **定时任务**  | `/api/v1/schedules`                                            | GET/POST/PUT/DELETE      |
| **技能**      | `/api/v1/skills`                                               | GET                      |
| **工具**      | `/api/v1/tools[/:name[/execute]]`                              | GET/POST                 |

### 认证机制

`getAuthHeaders()` 智能选择认证方式（按优先级）：

1. **API Key**（`X-API-Key` 头）—— OSS 模式首选
2. **JWT Token**（`Authorization: Bearer xxx`）
3. **X-User-Id**（开发模式回退）

**SSE 流特殊处理**：`EventSource` 不支持自定义 header，所以 `/api/v1/stream/sse` 通过 URL Query 参数传 `api_key` 或 `token`。URL 还支持 `last_event_id` 用于断点续传。

### SSE 流处理：`lib/shannon/stream.ts` (useRunStream hook)

监听 **40+ 种事件类型**，包括：

- `thread.message.delta` / `thread.message.completed`：流式 LLM 输出
- `WORKFLOW_STARTED/COMPLETED/FAILED` / `workflow.paused/resumed/cancelled`
- `AGENT_STARTED/THINKING/COMPLETED`、`TOOL_INVOKED/OBSERVATION`
- `DELEGATION/ROLE_ASSIGNED/TEAM_RECRUITED`
- `RESEARCH_PLAN_READY/UPDATED/APPROVED/REVIEW_USER_FEEDBACK`
- `SCREENSHOT_SAVED`、`WORKSPACE_UPDATED`
- `BUDGET_THRESHOLD`、`ERROR_OCCURRED/RECOVERY`

**高级特性**：

- **Delta 合并缓冲**：用 `requestAnimationFrame` 把同 stream_id 的多个 delta 合并后一次性 dispatch，避免 React 过度重渲染
- **断线重连**：指数退避（1s, 2s, 4s...），最多 10 次
- **流 ID 续传**：用 `lastEventId` 跟踪进度

### Redux 状态机：`lib/features/runSlice.ts`

整个对话状态都在 Redux 中（`events[]`、`messages[]`、`status`、`connectionState`），支持跨页面共享。**Redux Persist** 把 `selectedAgent`、`researchStrategy` 持久化到 localStorage。

**addEvent reducer 是核心**：根据 `event.type` 分别处理 40+ 种事件：

- `thread.message.delta` → 累积到对应 streaming message
- `WORKFLOW_COMPLETED` → 触发 `fetchFinalOutput()` 获取权威结果
- `RESEARCH_PLAN_READY` → 进入 review 模式
- `TOOL_OBSERVATION` → 解析截图并加入对话
- 复杂的去重逻辑（按 seq、stream_id、content hash）防止 SSE 重连导致的重复消息

## 🎨 视觉交互功能

### 1. **执行时间线**（`run-timeline.tsx`）

- 垂直时间轴 + 状态图标（completed 绿、running 蓝脉冲、failed 红）
- 每个事件可展开 `CollapsibleDetails`（带 JSON 语法高亮）
- Swarm 模式下根据 agent 染色（用 `agent-colors.ts` 生成稳定 hue）

### 2. **Radar 雷达可视化**（`components/radar/`）⚡

这是最炫酷的视觉特性。`RadarCanvas.tsx` 是一个用 **HTML5 Canvas 2D** 自绘的雷达动画：

- **飞机图标**：每个 agent 是一架朝向中心飞行的飞机
- **曲线轨迹**：根据 agent_id 用确定性 RNG（`createRNG`）生成曲线和螺旋路径
- **粒子尾迹**：飞机移动时留下渐隐的拖尾
- **到达脉冲**：飞机飞到中心时扩散的绿色脉冲环
- **Lead 指示器**：swarm-lead 触发金色脉冲 + 「LEAD」标签
- **暗色模式适配**：颜色随 `dark class` 切换
- **30Hz 刷新率**：通过 `requestAnimationFrame` 实现

`RadarBridge.tsx` 是看不见的"翻译器"，把 Redux 事件映射到 Zustand radarStore：

- 跳过内部 agent（orchestrator / planner / title_generator 等）
- 不同事件类型触发不同动作：spawn flight / extend estimate / accelerate to center / mark done

### 3. **Swarm Task Board**（`swarm-task-board.tsx`）

Swarm 模式下的多 Agent 协作看板：

- 显示 Lead 当前状态（金色 star）
- 任务列表（pending / in_progress / completed），每个任务显示分配的 agent
- Agent 颜色（HSL hue）按注册顺序自动分配

### 4. **Schedule Builder**（`schedule-builder.tsx`）

定时任务创建器：

- **Simple 模式**：4 个频率按钮（Hourly / Daily / Weekly / Monthly）+ 可视化时间选择
- **Advanced 模式**：直接编辑 Cron 表达式
- **预览**：实时显示未来 3 次执行时间
- 19 个常用时区下拉

### 5. **Workspace Panel**（`workspace-panel.tsx`）

会话级文件浏览器：

- **懒加载目录树**：点击文件夹才请求
- **多文件类型预览**：Markdown 渲染、JSON 高亮、图片 base64 展示、纯文本
- **下载按钮**：Tauri 模式下用 `saveFileDialog`，Web 模式下创建 Blob 触发下载
- **自动刷新**：监听 `WORKSPACE_UPDATED` / `SCREENSHOT_SAVED` 事件（500ms 防抖）

### 6. **会话摘要页**（Summary Tab）

4 个关键指标卡（总轮次/总成本/总 tokens/总时长）+ 按轮次明细 + **模型使用分布**（带彩色进度条和百分比）+ **参与的 Agent** 标签云 + 平均指标

### 7. **可拖拽右侧面板**

执行时间线和工作区可以**拖拽调整宽度**（cookie 持久化），拖到阈值以下自动折叠

### 8. **状态徽章 & 颜色系统**

- 状态徽章：amber（暂停）、red（取消/失败）、green（完成）、blue（运行中）
- Agent 类型颜色：Everyday 琥珀黄、Deep Research 紫罗兰、Web Automation 蓝
- 主题：next-themes 完整支持 light / dark / system

### 9. **Skill 选择**（`/skills` 页）

- 卡片网格视图，按 category 过滤
- 点击展开显示 Markdown 内容
- 「Use this skill」按钮：dispatch `setSelectedSkill` + 跳转到对话页

### 10. **能力检测 & Rate Limit 显示**

设置页显示分时段的 API 配额（每分钟/每小时剩余和上限）

### 11. **Tauri 桌面能力**（OSS 模式禁用）

`lib/tauri.ts` 是 stub；原生模式下有：系统托盘通知、Badge 角标、自动更新、文件系统访问

### 12. **Background Task Tracker**

`background-task-tracker.tsx` 在用户离开页面时仍在后台轮询运行中任务，任务完成时发系统通知

## 🛠️ 关键技术细节

### 输入适配

- `chat-input.tsx` 中用 `isComposingRef` 解决中文输入法 Enter 误触发送问题
- `fetchSessionHistory` 用渐进重试（1.5s → 3s → 5s）应对后端持久化延迟
- Fallback 轮询（30s）防止 STREAM_END 丢失
- 取消时 2 秒高速轮询直到 `workflow.cancelled` 确认

### 性能优化

- `RadarCanvas` 用 `ResizeObserver` + `requestAnimationFrame` 自适应
- `MessageItem` 用 `React.memo` + 引用稳定的 citations 缓存
- 引用稳定的 `getMarkdownComponents()` 避免每次重渲染
- ScrollArea 自动滚动到对话底部，但用户手动上滚后停止干扰
- 在 HMR 开发模式下裁剪 events 数组（>200 个只保留最后 150）

### 类型系统

- 完整的 TypeScript 强类型：`ShannonEvent` 联合类型涵盖 50+ 种事件
- `Message` 类型包含 SSE 重放去重用的 `_processedDeltas`
- 严格的事件 → Redux 状态映射

## 📌 总结

这是一个**工业级 AI 平台前端**，特色：

1. **统一抽象**：所有后端交互通过 SSE + REST 双向
2. **流式优先**：从消息、引用、进度、雷达飞机、文件树全部支持流式更新
3. **复杂状态机**：40+ 事件类型映射到 Redux 状态 + 大量去重和回放逻辑
4. **丰富可视化**：时间线 + Radar 雷达动画 + Swarm 看板 + 摘要统计图
5. **HITL 工作流**：研究计划多轮审核（feedback → ready → execute）
6. **多 Agent 编排**：swarm 模式下自动染色、任务分配、Lead 协调
7. **会话完整生命周期**：新建/列表/重命名/删除/搜索/自动保存标题
8. **平台无关**：一套代码同时支持 Web 浏览器和 Tauri 桌面

整个前端约 **6000+ 行 TS/TSX 代码**，完整封装了 Shannon 后端的复杂多 Agent 编排能力。
